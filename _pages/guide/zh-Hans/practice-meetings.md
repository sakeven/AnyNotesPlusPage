# 会议记录与跟进

开会时想认真听，又怕漏掉结论，常常只能一边说、一边赶着记。等到散会，笔记里留下了不少话，却不一定看得出哪些已经定了、哪些只是提议。

下面以一次发布前的项目讨论为例。团队要确定本次发布范围，还有测试和帮助文档没安排完。用 AnyNotes 录下讨论，会后核对结论，再把明确的任务设为提醒。

## 会前准备：议程和上次的结论

如果是一个会持续推进的项目，先建好[主题]({{ "/zh-Hans/guide/topics/" | relative_url }})，放入议程、上次的结论和这次要看的资料，再从主题里开始录音。以后补充的材料也放在这里，下次开会就不用重新翻找背景。

只有一次的短讨论，也可以直接从首页录音，不必为了记一场会先建立一套分类。先把内容留下来，之后再决定要不要归入主题。

## 录音时，随时看要点和转写稿

开始[录音]({{ "/zh-Hans/guide/recording/" | relative_url }})后，照常讨论。iOS 的 API Key 模式可以边录边看「实时整理」：现在主要在谈什么，还有哪些问题没有说清楚，接下来可能要做什么。需要核对一句话时，再切到「转写稿」。

讨论卡住时可以点「帮我想想」。例如大家已经说了几个方案，却一直没有判断标准，可以借助建议补问一句：“这次最在意的是时间、预算，还是结果的完整程度？”不需要每出现一条建议就打断大家。

录音中的整理适合帮你跟上讨论，不宜直接当成最终纪要。后面有人改口、补充或否定了一个方案，结论也可能跟着变化。

## 散会后，先分清「定了」和「还没定」

点击「完成」保存，等完整录音转写和整理结束，再打开笔记。先看结论，遇到日期、金额、名字或听起来不太确定的地方，回到原文核对。

接着从笔记进入「深入探讨」，让 AI 按你要发出去的形式整理。可以直接这样说：

> 帮我整理一份可以发给参会人的纪要。先写这次已经定下来的事，再列行动项，最后放还没定的问题。负责人和时间只用原话里明确说过的内容；没有说清楚的写「待确认」。提议过但最后没采用的方案，不要写成决定。

读结果时，尤其留意这三种说法：

| 讨论里说的是 | 纪要里应该怎样处理 |
| --- | --- |
| “这个方案可以考虑” | 留作候选方案，还没有决定 |
| “我周五前确认一下” | 记录确认任务，核对说话人和具体日期 |
| “这件事需要有人跟进” | 保留任务，但负责人仍待确认 |

发出纪要前，把「待确认」的几处问清楚。比如截图中的帮助文档还没有负责人，就需要再找人认领。

## 把需要跟进的事安排好

不是每一个行动项都需要提醒。先挑出确实有时间要求、又容易忘的事项，再在对话里提出具体要求：

> 周五上午十点提醒我向小林确认搜索测试结果，到点通知我。

在 iOS 授权了[提醒事项]({{ "/zh-Hans/guide/device-data/" | relative_url }})后，检查弹出的事项、日期、时间和通知设置，确认后再创建。只写到期时间，并不等于一定会在那个时间通知你。

录音过程中如果出现了可选操作，也要先查看再确认。出现建议或完成录音，都不会自动执行这些安排。

## 下次再聊，接着这次往下走

后续有人补充了报价、修改了日期，或完成了一项任务，就把新材料继续放进同一主题。下次讨论前，先看主题的最近变化和开放问题，再决定这次重点谈什么。

访谈也可以这样整理，只是提问要换一下：例如「按受访者的观点整理，每个观点保留一段原话，标出还需要追问的地方」。

录音中的实时整理需要 API Key；使用 Codex 登录时，也可以先录音，保存后再转写和整理。
